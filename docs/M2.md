# M2 — reliable local analytical platform

M2 adds dbt transformations and recovery around the checked M1 snapshot. It runs
locally with no database server, hosted dbt account, provider key, or model call.
The base CLI remains usable without the optional dbt dependency.

## Build and inspect

From the repository root:

```sh
UV_PROJECT_ENVIRONMENT=work/dbt-venv uv sync --locked --no-editable --extra dbt
work/dbt-venv/bin/chesslab demo
work/dbt-venv/bin/python -m chess_analytics.marts transform --dataset tiny
work/dbt-venv/bin/python -m chess_analytics.marts report-mart --dataset tiny
work/dbt-venv/bin/python -m chess_analytics.marts ops-report --dataset tiny
```

The first command needs package access unless uv has cached the lock's packages.
The remaining commands use the committed synthetic fixture. For the real historical
archive, complete the bounded M1 `foundation` ingestion and build first, then use
`transform --dataset foundation`. The dbt project is in [`dbt/`](../dbt/dbt_project.yml).
Its profile points only to the local candidate database set by the M2 wrapper;
dbt's anonymous usage statistics are disabled for that subprocess.

The lineage is `fact_game`/`fact_player_game` → `stg_games`/`stg_player_games` →
`int_game_eligibility` → `mart_game_outcomes` and `mart_player_outcomes`. The game
mart groups by observed UTC date and **exact** base/increment, retaining nulls.
The participant mart stays at player-game grain. They support descriptive counts,
not opening-effect or clock-pressure claims. Source opening tags are only counted
as present/missing; no opening classification is inferred.

Each transform copies a validated immutable M1 DuckDB file into an attempt
directory and runs dbt there. It reconciles accepted games, player rows, eligible
games, draws, unknown results, and marked bots against the governed M1 report.
Only after dbt tests and reconciliation pass does it publish an immutable mart
and atomically switch the mart pointer. The dbt manifest and result files stay
with the mart; stdout/stderr and failed candidates stay with attempts. M1 source
snapshots are never modified by dbt.

To backfill a known older checked snapshot without moving the current mart pointer:

```sh
work/dbt-venv/bin/python -m chess_analytics.marts transform --dataset tiny --snapshot-id SNAPSHOT_ID
```

To deliberately select a validated prior mart:

```sh
work/dbt-venv/bin/python -m chess_analytics.marts rollback-mart --dataset tiny MART_ID
```

An operational report lists ingestion, snapshot-build, and mart attempts; reasons,
coverage, observed elapsed/scanned bytes and throughput where recorded; source
versions/drift; disk bytes; and current pointers. Publisher checksum mismatch is
a failure; multiple observed source hashes for an unpinned local dataset produce
a warning. Peak whole-process memory was not measured and is reported as null.
The DuckDB memory setting is a configured limit, not a measured RAM claim.

## Acceptance evidence — 2026-10-03

- Tiny and foundation dbt builds each created five models and passed 19 dbt tests.
  The tiny mart reconciled 22 accepted games, 44 participant rows, 20 eligible
  games, and four draws. The foundation mart reconciled 121,332 games, 242,664
  participant rows, and 3,982 draws. See [tiny](../reports/M2-tiny-mart.json) and
  [foundation](../reports/M2-foundation-mart.json) manifests.
- A fresh dbt-only environment installed from the lock and ran the full offline
  suite: 23 tests passed. An injected pre-publication failure retained its
  attempt, kept the previous mart current, and retry matched a clean run.
  A failed dbt executable retained logs and left the M1 snapshot usable.
  Backfill did not move the current pointer; rollback validated the selected mart.
- Dagster materialized four assets with `CHESSLAB_WITH_DBT=1`; Prefect completed
  four local tasks with `--with-dbt`. These are local harness runs, not scheduler
  uptime evidence. [Foundation operations](../reports/M2-operations-foundation.json)
  include two ingestion attempts, two snapshot builds, one mart attempt, and no
  source drift across those foundation attempts.
- `uv lock --check --offline`, Ruff check/format, and the offline suite passed.
  No hosted CI run or model response is claimed.

The M2 recovery tests inject process-level failures. They do not certify
power-loss durability, general multi-source reconciliation, or unattended
processing while the laptop sleeps. Full source archives and warehouse files
remain Git-ignored. M3 can now add a bounded newer corpus and versioned
opening/clock metric contracts before analytical findings are claimed.
