# M6 measured-release work

M6 is **in progress**. The local analytics product and offline analyst remain usable.
No model response has been obtained or scored. The 50/50 M5 replay result checks the
harness, not AI accuracy. Its test labels were inspected during harness work, so
this version is not an untouched model holdout.

## Completed preparation

- Live-provider tool actions now run in a disposable child with a 30-second hard
  deadline. The child receives only `PATH` and `PYTHONNOUSERSITE`, uses the
  allowlisted checked tools, and cannot receive the provider key implicitly.
- A 12-case development pilot is frozen as 24 one-shot cells: typed planner with
  metric IDs versus the same planner plus governed metric definitions. The
  model, dataset, output limit and tool set are shared. This tests the semantic
  context within the typed architecture; it is **not** the spec's schema-only
  SQL baseline, because free-form SQL is still disabled.
- [Proposed preflight](../reports/M6-proposed-preflight.json) uses the official
  [GPT-6 Luna pricing](https://developers.openai.com/api/docs/models/gpt-6-luna)
  of $0.10/M input and $0.50/M output, 512 maximum output tokens, and a
  *hypothetical* $1 cap. It quotes a conservative $0.0198638 for all 24 cells.
  This is a quotation, not observed spend or confirmed account entitlement.
  The live runner recomputes every request and verifies frozen hashes before
  any transport. It reserves the entire run under the explicit cap, makes no
  retries, retains each response or failure locally, and stops after an unknown
  or failed attempt rather than treating its cost as zero.

## Live gate and next sequence

A user-controlled personal configuration must set `enabled: true`, acknowledge
the personal account, name a verified model and current prices, and specify a
positive total run cap. The only key variable read is
`CHESSLAB_PERSONAL_OPENAI_API_KEY`; no key belongs in JSON or Git. The tracked
example remains disabled. Do not use workplace credentials.

Once those inputs exist, run `python -m analyst_m5.experiment prepare --config
<private-config> --preflight <private-preflight>` and inspect the exact quote.
Then run the same module with `run`. Attempt records go under ignored
`data/analyst_attempts/<experiment-id>/`. A live result still needs manual
review of analytical caveats and high-severity cases. Numerical and abstention
rates, paired changes, all failures, latency and gross costs must be reported
with exact denominators. One pass provides no repeatability claim. A genuine
held-out benchmark needs a fresh unseen family split, and the SQL baseline
needs an independently isolated restricted SQL track; neither is implied by
this pilot.

Release targets stay those in `PROJECT_SPEC.md`: passing offline integrity and
access checks, 90% numerical and 90% ambiguity/insufficient handling, no
high-severity evidence fabrication/access failures, traceable claims, and no
unhandled release-case crashes. They are targets, not achieved results.
