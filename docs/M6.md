# M6 measured-release work

M6 is **in progress**. The local analytics product and offline analyst remain usable.
An actual 24-cell development pilot has run, but release accuracy gates were
missed. The 50/50 M5 replay result checks the harness, not AI accuracy. Its
test labels were inspected during harness work, so this version is not an
untouched model holdout.

## Completed preparation

- Live-provider tool actions now run in a disposable child with a 30-second hard
  deadline. The child receives only `PATH` and `PYTHONNOUSERSITE`, uses the
  allowlisted checked tools, and cannot receive the provider key implicitly.
- A 12-case development pilot is frozen as 24 one-shot cells: typed planner with
  metric IDs versus the same planner plus governed metric definitions. The
  model, dataset, output limit and tool set are shared. This tests the semantic
  context within the typed architecture; it is **not** the spec's schema-only
  SQL baseline, because free-form SQL is still disabled.
- [Proposed preflight](../reports/M6-proposed-preflight.json) uses the official
  [GPT-6 Luna pricing](https://developers.openai.com/api/docs/models/gpt-6-luna)
  of $0.10/M input and $0.50/M output, 512 maximum output tokens, and a
  *hypothetical* $1 cap. It quotes a conservative $0.0198638 for all 24 cells.
  This is a quotation, not observed spend or confirmed account entitlement.
  The live runner recomputes every request and verifies frozen hashes before
  any transport. It reserves the entire run under the explicit cap, makes no
  retries, retains each response or failure locally, and stops after an unknown
  or failed attempt rather than treating its cost as zero.
- A [fresh local clone](../reports/M6-fresh-clone.json) installed the locked
  production, dashboard and dbt dependencies offline from a filled platform
  cache, then passed the tiny demo: 22 accepted of 26 seen and draw rate 4/20.
  The first cache-only attempt failed because two selected macOS wheels were
  missing; those wheels were subsequently acquired into the local cache. The
  repository does not vendor dependencies or the ignored analytical corpus.

## Live gate and next sequence

The user selected a $0.10 gross-spend cap across this pilot's attempts. Four
frozen prompt revisions made **32 actual API requests**, including three
stopped development runs. Every response, failure, usage record and model text
was retained; the key-free export is [M6 live pilot](../reports/M6-live-pilot.json)
and the final request freeze is [M6 live preflight](../reports/M6-live-preflight.json).
Observed gross API cost was **$0.0046302** across all revisions, of which
$0.0033568 was the final 24-cell run. This is gross cost even if account
credits cover it. The resolved model reported by the API was `gpt-6-luna`.

The final one-shot development run completed 24/24 without execution failures
and passed the frozen scorer on 16/24 cells: 8/12 answerable and 8/12
ambiguity/unsupported. Both conditions passed 8/12. One condition gained a
correct proxy case while the other lost a different one; there is no credible
semantic-context advantage in this small, inspected development set.
The scorer rejected two numerically correct proxy answers because they used
`analyze_clock_pressure`, an equivalent checked wrapper, instead of its
expected `query_metric` call. The multi-step opening comparison failed in
both conditions. Monthly extrapolation and private-file requests got
`needs_clarification` instead of the expected `unsupported`; neither executed
a tool or produced a fabricated value. This failure review was by the coding
agent, not a blinded human reviewer. The 90% numerical and abstention targets
remain **unmet**; M6 is not accepted as a measured release.

The first live request exposed an unsupported extra tool argument; a second
exposed invented filter keys; a third stopped on title-case `Black`. Their
records and costs remain in the report. Fixes were made only on these
development cases, then the final prompt was frozen before its 24 cells.
No untouched held-out model result or repeatability claim exists.

For a future run, a separate provider JSON file is optional. The defaults
verified against the [official model page](https://developers.openai.com/api/docs/models/gpt-6-luna)
on 2026-10-03 are `gpt-6-luna`, $0.10/M input, $0.50/M output, and 512 maximum
output tokens. The operator still supplies an **explicit total gross-spend cap**.
After choosing a cap, run:

```sh
python -m analyst_m5.experiment prepare --max-run-usd <chosen-cap> --preflight work/m6-preflight.json
python -m analyst_m5.experiment run --max-run-usd <same-cap> --preflight work/m6-preflight.json --env-file work/.env
```

Inspect the preflight before the second command. `prepare` never reads a key;
`run` reads only `CHESSLAB_OPENAI_API_KEY` from the named env file if it is not
already set in the process environment. No key belongs in JSON or Git. The
tracked provider example remains disabled. Do not use workplace credentials.
`--config <private-config>` remains available instead of `--max-run-usd` for
later model/pricing changes; reverify prices when changing model or running
on a later date. Attempt records go under ignored
`data/analyst_attempts/<experiment-id>/`. A live result still needs manual
review of analytical caveats and high-severity cases. Numerical and abstention
rates, paired changes, all failures, latency and gross costs must be reported
with exact denominators. One pass provides no repeatability claim. A genuine
held-out benchmark needs a fresh unseen family split, and the SQL baseline
needs an independently isolated restricted SQL track; neither is implied by
this pilot.

Release targets stay those in `PROJECT_SPEC.md`: passing offline integrity and
access checks, 90% numerical and 90% ambiguity/insufficient handling, no
high-severity evidence fabrication/access failures, traceable claims, and no
unhandled release-case crashes. They are targets, not achieved results.
